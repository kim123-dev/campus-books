# 화면 이동 속도 측정

운영 사이트에서 목록 → 상세 → 쪽지함 → 프로필 화면이 "본문이 그려질 때까지" 걸리는 시간을 잰다.
정적 파일 캐시 우선 서비스 워커와 쪽지함·프로필 동시 요청(커밋 `0c9e1a3`) 전후를 비교하려고 만들었다.

## 측정 조건

- 대상: 운영 사이트 `https://campus-books-production.up.railway.app` (앱·DB는 미국 서부, 접속 지점은 도쿄 엣지)
- 측정한 곳: 한국 가정용 회선, Windows 11, 헤드리스 Chrome, 화면 375×812 (모바일)
- 시간: 화면 주소로 이동한 순간부터 본문 조건이 처음 참이 된 프레임까지 (`performance.now()`)
  - 목록: 글 카드가 하나 이상 / 상세: 글 정보 / 쪽지함: "불러오는 중"이 바뀜 (로그아웃 상태면 로그인 화면으로 넘어감) / 프로필: 후기·글 요약이 모두 채워짐
- 상황 세 가지, 각 3회 반복한 중앙값
  - 첫 방문: 새 브라우저 프로필
  - 재방문(캐시 유효): 같은 브라우저에서 바로 다시
  - 재방문(브라우저 재시작): 브라우저를 끄고 150초 뒤 같은 프로필로 다시 (브라우저가 추정하는 캐시 기간이 지난 뒤)
- 로그인 상태는 측정용 계정을 만들어 쟀고, 측정이 끝난 뒤 탈퇴 처리했다.

읽는 법

- 가장 크게 줄어든 것은 브라우저를 껐다 켠 재방문이다. 전에는 정적 파일마다 서버에 다시 확인(왕복 약 0.2초)했지만, 이제는 서비스 워커 캐시에서 바로 나온다. 남은 시간은 대부분 API 응답 대기다.
- 첫 방문의 쪽지함·프로필이 빨라진 것도 서비스 워커 덕분이다. 목록 화면이 뜬 뒤 서비스 워커가 정적 파일 44개를 미리 받아 두기 때문이다.
- 첫 방문의 목록·상세는 비슷하거나 조금 느리다. 목록은 서비스 워커가 없는 첫 화면이고, 상세는 그 사이 서비스 워커가 글꼴(약 800KB)을 포함한 파일을 뒤에서 받느라 회선을 나눠 쓴다. 3회 중앙값이라 ±150ms 정도는 회선 편차 안이다.

## 첫 번째 "후" 측정이 무효였던 이유

배포 직후 처음 잰 "후" 결과는 서비스 워커가 한 번도 설치되지 않아(설치 오류 `Failed to execute 'addAll' on 'Cache': Entry already exists.`) 비교에 쓰지 않았다.

- 원인(확인됨): Windows 경로 길이 제한(260자). 측정 스크립트가 Chrome 프로필을 결과 폴더 안에 만들었는데, 결과 폴더 경로가 길어 서비스 워커 캐시 파일 경로가 260자를 넘었다. 이때 Chrome은 캐시 파일을 하나도 만들지 못하고 위 오류로 설치를 취소한다.
  - 같은 스크립트로 캐시 파일 경로가 256·258자인 폴더에서는 44개 모두 저장되고 설치됐고, 261·265자인 폴더에서는 0개였다.
  - 처음에는 Chrome 디버깅 포트 재사용을 의심했지만, 포트를 매번 바꿔도 같은 오류가 나서 원인이 아니었다.
- 고친 방법: Chrome 프로필을 짧은 임시 폴더(`os.tmpdir()` 아래)에 만들고 측정이 끝나면 지운다.
- 실제 사용자와는 관계없다. 실제 브라우저로 운영 사이트를 열어 서비스 워커가 정상 설치되고 캐시에 44개 파일이 담긴 것을 직접 확인했다.
- 같은 일이 다시 생기지 않게, 측정 결과에 화면마다 서비스 워커가 맡았는지(`controlled`)와 설치 오류(`swErrors`)를 남기고, 비교할 때 서비스 워커가 맡았어야 하는데 맡지 않은 측정은 빼고 그 수를 따로 보여준다.

## 사용법

```bash
# 측정 (결과: <출력 폴더>/results.json). 반복 3회면 150초 대기 포함 약 7분
node tools/perf/measure.mjs tools/perf/out/before 3

# 로그인 상태로 측정
TOKEN=<로그인 토큰> node tools/perf/measure.mjs tools/perf/out/before-login 3

# 한 결과의 화면별 중앙값과, 한 실행에서 나간 요청 목록
node tools/perf/report.mjs tools/perf/out/before/results.json

# 전후 비교 표
node tools/perf/compare.mjs tools/perf/out/before/results.json tools/perf/out/after/results.json
```

환경 변수 (모두 선택)

| 이름 | 뜻 | 기본값 |
|---|---|---|
| `BASE` | 측정할 주소 | 운영 사이트 |
| `TOKEN` | 로그인 토큰. 없으면 쪽지함은 로그인 화면으로 넘어가는 시간을 잰다 | 없음 |
| `LATENCY` | 네트워크 요청마다 더할 지연(ms). 로컬 서버를 운영과 비슷한 왕복 시간으로 잴 때 | 0 |
| `COLD_WAIT` | 브라우저 재시작 재방문 전 기다릴 초 | 150 |
| `CHROME_PATH` | Chrome 실행 파일 | 흔한 설치 경로에서 찾음 |
| `CDP_PORT` | 첫 Chrome의 원격 디버깅 포트 (띄울 때마다 1씩 늘림) | 9444 |

- 목록의 첫 글과 그 판매자로 상세·프로필 주소를 정하므로, 글이 하나도 없으면 잴 수 없다.
- `tools/perf/out/`은 커밋하지 않는다.
